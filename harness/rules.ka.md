## სტეკი

- პაკეტების მენეჯერი: <npm | pnpm | yarn | uv | poetry | go mod>
- ბაზა: <მაგ. Postgres 16, Prisma-ს გავლით>
- სად იდეპლოება: <მაგ. Vercel | Fly.io | საკუთარი სერვერი>

## ბრძანებები

გამოიყენე ზუსტად ეს ბრძანებები. ვარიაციები არ მოიგონო.

```
install     <npm ci>
dev         <npm run dev>
test        <npm test>
ერთი ტესტი  <npm test -- <path>>
lint        <npm run lint>
typecheck   <npm run typecheck>
build       <npm run build>
```

## სტრუქტურა

მხოლოდ ის, რაც კოდზე შეხედვით არ ჩანს:

- <src/lib/ საერთო კოდია; src/app/ მხოლოდ მარშრუტები — ლოგიკა მარშრუტის ფაილში არასდროს>
- <ბაზასთან წვდომა მხოლოდ src/db/*-ის გავლით, პირდაპირი კლიენტი კომპონენტში არასდროს>
- <ტესტები დევს ფაილის გვერდით, სახელით *.test.ts>

## როდის ითვლება დასრულებულად

არაფერია დასრულებული, სანამ ეს ყველაფერი არ გადის:

- `<npm test>` გადის
- `<npm run typecheck>` გადის შეცდომების გარეშე
- `<npm run lint>` გადის ახალი გაფრთხილებების გარეშე
- ახალ ქცევას აქვს ტესტი, რომელიც ცვლილების გარეშე ვარდება

## მკაცრი აკრძალვები

- არასდროს დააყენო, განაახლო ან წაშალო პაკეტი წინასწარ კითხვის გარეშე
- არასდროს შეცვალო ფაილები `<migrations/ | .github/ | infra/>` საქაღალდეში
- არასდროს გაუშვა `git push --force`, `git reset --hard` საერთო ბრენჩზე, ან `rm -rf`
- არასდროს ჩააკომიტო საიდუმლოები, `.env` ფაილები ან ნებისმიერი წვდომის მონაცემი
- არასდროს გამორთო ტესტი, ტიპების შემოწმება ან lint-ის წესი იმისთვის, რომ რაღაც გავიდეს.
  გაასწორე მიზეზი ან გაჩერდი და მოახსენე.
- არასდროს შეცვალო საჯარო API `<src/api/>`-ში ისე, რომ ანგარიშში ცალკე არ დაწერო

## კოდის სტანდარტები

<დატოვე მხოლოდ ის, რასაც ფორმატერი უკვე არ აკეთებს.>

- <`any` არ გამოიყენება. თუ ტიპი მართლა უცნობია, გამოიყენე `unknown` და დაავიწროვე.>
- <შეცდომას ემატება კონტექსტი; შეცდომა ჩუმად არ ისრისება.>
- <ფუნქცია, რომელიც შეიძლება ჩავარდეს, აბრუნებს result-ტიპს; გამონაკლისი მხოლოდ პროგრამისტის შეცდომისთვისაა.>
- <კომპოზიცია სჯობს მემკვიდრეობას; ერთ დონეზე ღრმა იერარქია არ იქმნება.>

## როგორ უნდა მოიქცე

ეს ყველა დავალებაზე ვრცელდება, ამიტომ ცალკეულ პრომპტებში აღარ მეორდება.

- **ანგარიში მუშაობის პარალელურად.** ყოველი შეცვლილი ფაილის შემდეგ დაბეჭდე ფაილის სახელი და
  ერთი ხაზი იმაზე, რა შეიცვალა.
- **ნაგულისხმევად — ნაკლები ზიანი.** როცა ინსტრუქცია ორაზროვანია, აირჩიე ის წაკითხვა, რომელიც
  ყველაზე ნაკლებს შლის, და დაწერე, რომელი აირჩიე.
- **გაჩერდი შეცდომაზე.** თუ ბრძანება ან ინსტრუმენტი ჩავარდა, გაჩერდი და მოახსენე რეალური
  შეცდომა. არასდროს გამოიგონო შედეგი და არასდროს გააგრძელო დაშვებაზე დაყრდნობით.
- **მცდელობების ლიმიტი.** ერთი და იმავე მიდგომით სცადე მაქსიმუმ 2 ჯერ. შემდეგ გაჩერდი და
  დაწერე, რა სცადე.
- **გადაამოწმე, ნუ დაასკვნი.** „მუშაობს“ ნიშნავს, რომ ბრძანება გაუშვი და გავიდა. საკუთარი
  დიფის წაკითხვა ვერიფიკაცია არ არის.
- **არეალის გაფართოებამდე იკითხე.** თუ გამოსწორებას მითითებული არეალის გარეთ მყოფი ფაილი
  სჭირდება, გაჩერდი და დაწერე — თვითონ ნუ გააფართოებ.
- **ჩუმი დალაგება არა.** არ გადააფორმატო, არ გადაარქვა და არ „დაალაგო“ კოდი, რომელიც
  დავალების ნაწილი არ არის.
